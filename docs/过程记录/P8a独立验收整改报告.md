### O3：保留历史基线的依据

| 文件 | 职责 | 维护方式 |
|---|---|---|
| 根schema-v7.sql | 唯一当前DDL权威源 | 新DDL先编辑此处，建立相应新迁移 |
| django/sql/schema-v7-current.sql | 应用打包所需的当前完整快照 | 由同步工具生成，不能独立编辑；本地检查及CI校验一致性 |
| django/sql/schema-v7.sql | P7冻结基线，供core/0001_initial执行 | 禁止覆盖、删除或重新计算迁移哈希 |
| django/sql/p8a-item-qr.sql | P8a独立增量，供catalog/0002执行 | 固定SHA，测试校验与权威源P8a章节一致 |

冻结基线SHA-256仍为 `2cc1062a3386ed9815fce2fbb60b05df8d3b5827d70fec9a586b5543ac367f82`；P8a增量仍为 `c2984037239667a377f6678dcaa7c0c37497cf1ee1d023e9f511783b7727fa6d`。本次未修改这两份SQL或已发布迁移。

若直接用当前完整schema覆盖冻结文件，初始迁移将因SHA不符而失败；若同时重写旧哈希，则会破坏迁移可复现性，并让后续增量重复添加qr_token。因此本次采用“唯一当前源 + 自动生成快照 + 不可变历史迁移”的方案。完整操作约定见 [SQL制品说明](../../django/sql/README.md)。
