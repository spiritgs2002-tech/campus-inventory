## 2. P1 实现

- `core/0001_initial`：手写迁移，通过 `RunSQLFile`（`migrations.RunSQL` 子类）先整文件执行 schema-v7.sql，再整文件执行 grant-runtime.sql。源文件不拆分、不重写，初始迁移固定 SHA-256，制品被改动则拒绝执行。
- schema 自带 BEGIN/COMMIT，因此设置 `atomic=False`，保留原 SQL 自有事务。注入提交前故障验证了整个 schema 回滚，不残留表或函数。
- 其余 4 个迁移只用 `SeparateDatabaseAndState(database_operations=[])` 保存 ORM 状态，不生成 DDL。共 **5 条迁移记录**，没有使用自动生成 DDL 的迁移。
- 建立 **27 个 managed=False 模型，315 个数据库字段、104 个 ForeignObject 关系**；全部字段名/空值属性和外键列序已逐表与真实 PostgreSQL 目录比对。
- 两张无 id 的表（login_throttle、scrap_attachments）使用 Django 5.2 原生复合主键；没有伪造 id。跨 app 关联使用字符串名称。
- 映射 4 个 PostgreSQL 存储生成列；两个 created_xid 字段通过自定义只读映射在 INSERT 后 RETURNING 数据库触发器值，不将 xid8 当作 bigint。
- `apply_schema`：通过 Django 迁移记账重复执行；存在未记账业务表时拒绝自动接管/覆盖。`verify_schema` 断言 27/14/32；`verify_runtime` 执行实际授权断言。

## 3. 授权脚本适配

原 grant 脚本对 public 下全部表授权，会将新增加的 `django_migrations` 也授予运行角色写权限，破坏运行/迁移账号分离。因此同步修改 `v7-tools/grant-runtime.sql`、`verify-runtime.sql` 及 Django 打包副本：

1. 撤销 inventory_runtime 对 Django 迁移记账表及序列的权限。
2. verify 对记账表做专门的“不可修改、不可拥有”断言，再对 27 张业务表执行原有断言。
3. 增加 rolcanlogin 检查，确保 inventory_runtime 本身始终 NOLOGIN。

没有修改 schema-v7.sql 的任何字节；其 SHA-256 仍为：

`2cc1062a3386ed9815fce2fbb60b05df8d3b5827d70fec9a586b5543ac367f82`

## 5. 事务与范围边界

- schema 文件、grant 文件、Django 迁移记账各有自己的提交边界，**不是共同原子提交**。保留原文件 BEGIN/COMMIT 与整文件执行后，不声称 grant 失败可以撤销已成功提交的 schema。若此阶段失败，命令拒绝自动 fake/接管，应由 DBA 恢复已验证备份或重建尚未使用的专用测试库；无破坏性 downgrade。
- 日常服务仍须使用普通运行 LOGIN，不能使用测试 DBA 或迁移 owner。原授权断言与本次真实 LOGIN 用例均不能替代部署时对实际生产登录身份的核验。
- 本期没有实现 P2 的会话族/JWT/RBAC，也没有开放未鉴权业务 CRUD。服务层过滤和四通路租户隔离仍按后续 Phase 完成。P1 仅验证数据库复合外键拒绝跨租户关系，不等于整个应用隔离验收通过。
- 对账 13 项业务异常构造、并发核算与性能不属于本期结论；未将空库对账当作业务验收。

## 6. WorkBuddy 复验步骤

在 `inventory-v4/django/` 执行：

```sh
uv sync --frozen
export DEBUG=true
export SECRET_KEY="$(python3 -c 'import secrets; print(secrets.token_urlsafe(64))')"
export ALLOWED_HOSTS=localhost,127.0.0.1,testserver
export DB_HOST=/tmp DB_PORT=55432 DB_USER=postgres DB_NAME=postgres
uv run python manage.py check
uv run python manage.py precheck_sql
uv run python scripts/verify_p1.py
```

以上 DBA 连接仅用于测试脚本创建专用测试库，**不要在 postgres 维护库上手动运行 apply_schema/migrate**。独立测试 PostgreSQL 集群中，执行登录需 CREATEDB/CREATEROLE；脚本自行清理其创建的数据库及登录身份。
