## 相对 v3 的主要变化

| v3问题 | v4处理 |
|---|---|
| 幂等键只有普通索引 | 独立operation_requests，按租户/操作者/操作/键唯一，保存摘要和响应 |
| 流水没有库位 | 易耗品流水加入库位与质量，与inventory相同维度 |
| 单明细只容一张资产卡 | outbound_assets承载实际逐件发放，申请量与实际卡清单分离 |
| 来源关系缺失 | 归还引用原发放，采购退货引用原入库；资产卡来源同物资复合外键 |
| 损坏品可混入可领用库存 | available/damaged分账；发放只扣available |
| 跨校关联可入库 | 业务外键带tenant_id；物资分类/卡片/库存的类型外键同步约束 |
| 部分发放剩余量未定义 | 一次执行、差额关闭并填原因；再次领取重新申请 |
| 在用资产报废冲突 | 原领用人可申请，执行前必须归还，通过历史发放记录保留依据 |
| 部门耗材报损没有持有量账 | 一期仅仓库报损；不二次扣减已领用耗材 |
| 建卡后禁止采购退货 | 允许符合条件的在库卡片逐件退货 |
| 固定资产流水强填余额 | 单独asset_events，stock_ledger仅记录耗材 |
| 学校管理员可开通租户 | 一期租户生命周期改为受控运维命令 |
| 恢复演练在试点后 | 移到真实数据试点前；小程序/盘点作为独立二期 |

## DDL 与应用职责边界

SQL已包含同租户外键、物资类型约束、库存非负、数量形状、自批字段一致性、来源唯一性及追加式历史保护。以下是必须实现的事务规则，不能误称为DDL已自动保证：

1. 业务角色授权、用户/租户启用状态、目录字段裁剪及文件访问控制。
2. 单据pending状态锁、已执行单据不可修改、资产合法状态迁移、审批开关快照从锁定的租户记录取得。
3. 发放完成时 actual_qty 与资产清单条数相等；领用资产只能in_stock，采购退货资产同样必须在库且无责任人。来源单据必须为采购类型。
4. 归还来源必须为已执行领用明细；资产归还时原发放卡片、物资、责任人一致，更新returned_at、库存/卡片与事件同事务。若同时存source_outbound_item_id与source_outbound_asset_id，必须指向同一次发放。
5. 累计耗材归还量/供应商退货量不超来源数量；此处须锁来源行，不能仅查询汇总后无锁写入。
6. 固定资产采购入库数量与创建卡数一致，归还不生成新卡；opening入库对应导入任务。期初质量状态与资产状态对应。
7. 耗材流水的item、库位、质量、数量与来源明细一致；固定资产事件的卡片与来源记录一致，事件名称/前后状态/来源类型相符。
8. 所有库存变动均写流水；缺行先安全建立再锁定。固定资产领用只写资产事件，不动耗材inventory。
9. operation_requests在事务开始占位时可先存空JSON响应，成功前写最终响应；任何失败必须回滚占位记录，禁止单独提交空响应。命中已提交键需检查摘要并重放已保存响应。
10. 幂等请求记录保留到业务记录归档，不随7天临时文件清理。随机QR token由服务端生成；唯一索引本身不提供随机性。

## 验收用例

| 类别 | 必测场景与预期 |
|---|---|
| 租户关系 | A校用户引用B校部门/物资/单据，复合外键拒绝；读取接口返回403/404，不泄露记录 |
| 幂等 | 同键同请求重复20次只执行一次；同键不同请求409；不同键重复执行已完成单不再次扣库 |
| 并发库存 | 库存10，20个请求各领1，成功总量≤10；同库位不存在库存行时两笔入库合计不丢失 |
| 资产发放 | 申请5台实发3台，关联3张卡并关闭差额；两个管理员争抢同一卡只一方成功 |
| 归还 | 耗材实发3累计归还最多3；同一资产发放记录只能归还一次；再次发放后允许新的归还 |
| 采购退货 | 耗材来源额度与当前库存均充足才能执行；已建卡的在库资产允许退货；在用/终态禁止 |
| 质量隔离 | damaged不计入可领用库存；损坏资产归还转repair；损坏耗材归还进入damaged库存 |
| 报废 | 领用人可申请本人资产，未归还不能审批执行；归还后可审批；管理员仓库报损扣指定库位质量 |
| 自批 | 关闭开关拒绝同人审批；打开后同人审批记录快照与标红；非同人审批不能伪标自批 |
| 对账 | 按学校/物资/库位/质量汇总流水，与inventory逐项相等；固定资产按卡片与事件重放核对 |
| 导入 | 错误预览不入账；确认第4999行失败整批回滚；重复确认不重复创建期初流水 |
| 恢复 | 独立环境恢复数据库与密钥，可解密手机号、验证盲索引并对账；测量RPO/RTO |

## 本次验证范围

已进行结构静态复核：22张表、表引用及复合外键的目标唯一键；数量/状态/来源规则与计划逐项比对。当前环境没有psql和Docker，本次未执行PostgreSQL建库或并发验收。M0必须在约定PostgreSQL版本上验证DDL和Alembic迁移；本文不把静态复核当作数据库执行通过。

本方案没有替学校决定具体云服务商、预算、教职工数据留存期限或对外服务手续；这些在试点上线前落实。未增加学生资料、部门耗材持有账、费用结算与折旧计算等业务范围。
