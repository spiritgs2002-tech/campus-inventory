# 应用级「上线运行」验证报告（沙箱实测）

- **日期**：2026-10-31
- **性质**：在沙箱内直接运行应用代码（无需 Docker），验证「系统能否真正跑起来」；与 Mac Docker 跑的是同一份代码与同一套 compose 逻辑，可提前排除应用层风险。
- **环境**：Python 3.13.12 · PostgreSQL 16.15（127.0.0.1:55432）· Django 5.2 · gunicorn · psycopg3。
- **限制**：沙箱**无 Redis**、**无 Docker**；故 `ready` 探针的 redis 子项、以及容器编排（web/worker/beat/nginx）须在 Mac Docker 中验证。

应用代码与运行时配置**可正常上线运行**：数据库 schema 完整、运行身份权限正确、生产配置无问题、服务可启动、鉴权链路（租户→DB→运行身份→JWT）真实打通、回归测试全绿。

## 备注
- 测试套件按 CI 配置以 `postgres` 超级用户连接（可建测试库 + `SET ROLE inventory_runtime`）；**生产运行时身份为 `inv_run`**，角色分离约束成立。
- 沙箱 PG 对 `postgres` 走 TCP 信任；为跑通测试已为 `inventory_app` 补 `CREATEDB/CREATEROLE`（迁移 owner 本就该有，符合生产预期）。
- 沙箱仅在验证期间临时启动 gunicorn（已关闭），测试库自动销毁；未新建持久痕迹。
