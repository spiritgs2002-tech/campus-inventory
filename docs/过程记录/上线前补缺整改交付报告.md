## 二、对指令包现状说明的核实

1. B6 所称“原CI未执行146项套件”并不准确：原工作流调用的 `scripts/verify_p1.py` 已经执行 `manage.py test tests --noinput -v2`。本次保留这一回归网，同时按要求新增显式步骤，使完整套件在 CI 界面独立可见。
2. 不直接照抄全局 `DB_NAME=postgres` 下的 `apply_schema` 示例。工作流先创建专用基线，再在该库迁移及测试。Django默认建立新测试库并应用迁移，并非自动克隆原库全部授权；cluster级运行角色及各测试库中的授权由既有基线迁移建立，测试夹具继续执行 `SET LOCAL ROLE inventory_runtime`，独立脚本继续使用真实普通LOGIN核验权限。
3. 就绪示例中的 `str(e)` 会公开内部连接信息，且仅有连接超时不能限制 Redis 读取卡住。本次返回固定依赖状态，并同时限制连接/读取时间，异常原文不进入该探针响应或日志。
