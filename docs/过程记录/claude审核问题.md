# claude 审核问题：实施计划 v7（最终版）及 schema-v6.sql、v6-tools

审核日期：2026-10-31。审核对象：`实施计划v7_最终版_.md`，并对照 `schema-v6.sql`、`grant-runtime.sql`、`verify-runtime.sql`、`reconcile.sql`、`README.md`、`实施计划v6.md`、`实施计划v5.md`。

**方法与局限**：只做静态阅读和脚本检查。本机没有 PostgreSQL，没有执行过任何 SQL。`v5审核逐项答复与v6验收说明.md` 和 `ARCHITECTURE.md` 不在提供的材料里，涉及它们的内容我无法核实。

## 一、我核对过的结论

| 项 | 结果 |
|---|---|
| v7 的 P0：4 个函数开头是单个 `$` | **属实**。`schema-v6.sql` 第 383、395、414、441 行是 `AS $`，闭合处是 `$$;`。其余 7 个函数（532、546、558、568、572、586、600 行）写法正确。 |
| 表数量 27、函数数量 11 | 属实。 |
| 外键引用的目标列组合是否都有 PK/UNIQUE，引用的列是否存在 | 把 4 个坏函数体忽略后，扩展脚本检查 27 张表，0 处缺失（含 ALTER 补加的外键）。 |
| v7 的 P1-1（verify 缺 DELETE/UPDATE 负向断言） | 属实。`verify-runtime.sql` 只对三张历史表检查了 UPDATE/DELETE。 |
| v7 的 P1-2（会话整族清理无实现） | 属实。schema 里只有 `idx_session_expiry` 索引，没有清理函数。 |

结论：v7 自己列出的缺陷基本准确。下面是它**没有列出**或**处理方式有问题**的部分。

## 三、中等问题

| # | 位置 | 问题 | 建议 |
|---|---|---|---|
| B1 | v7 §0.3 P1-3、§2 | **“最低 PG13”不合适。** `pg_current_xact_id()` 只是技术下限。按 PostgreSQL 的 5 年支持周期，PG13 已在 2025 年底结束支持（以官方版本策略页为准）。新系统不应把已过期版本写成支持下限。 | 支持下限与测试基线统一为 PG16；技术下限写在注释里说明即可。 |
| B2 | v7 §4 | “禁止创建过程中跨事务或**保存点**拆分头与明细”。按 PostgreSQL 文档，`pg_current_xact_id()` 返回的是顶层事务 ID，保存点内不变，所以保存点不会破坏守卫，真正要禁止的是跨事务。 | 修正措辞；M0 用测试验证。我未实测。 |
| B3 | `grant-runtime.sql` | **运行角色对所有表有 INSERT/UPDATE，包括 `tenants`。** 运行账号可以改租户的 code、状态、到期日和资产编号计数，与“租户开通/期限只走受控运维、学校管理员不能延期”在数据库层不一致。 | `tenants` 只给列级 UPDATE（自批开关、显示信息、编号计数），不给 INSERT；`verify-runtime.sql` 加相应断言。 |
| B4 | `attachments` 表 | **证据附件元数据没有完整性保护。** 运行角色可以 UPDATE `sha256`、`object_key`、`size_bytes`、`retention_until`、`legal_hold`。v7 说“证据元数据长期保留”，但数据库层没有保证。 | 加触发器：只允许 `deleted_at` 单向写入，且必须 `retention_until` 已过期且 `legal_hold=false`；`retention_until` 只能延长；其余列不可改。 |
| B5 | v7 §0.4 P2-1 | **“证据附件任何阶段不可删”被放在“随实现消化”，但它是需要现在决策的合规问题。** 误传含学生个人信息的文件，关联行无法删除。 | 现在决定：pending 阶段允许撤回关联（触发器放行父单 pending 时的 DELETE），并配合对象存储清理。 |
| B6 | `reconcile.sql` | **缺“单据↔流水”完整性检查。** 现在只查“库存 = 流水累计”。如果一张已完成的单据既没写流水也没改库存，这个检查发现不了。 | 增加：每个已完成的耗材出入库明细、每个审批通过的报损/调整明细，各有且仅有对应数量和方向的流水；资产类单据各有对应事件。 |
| B7 | `reconcile.sql` | **没核对流水的滚动结余 `balance_after`**，也没核对采购退货累计额度。 | 用窗口函数对每个库存维度核对滚动结余；采购退货累计 ≤ 采购量。 |
| B8 | `reconcile.sql` 的 `asset_latest_event` | **资产位置口径未定义。** 对账把卡片的 `location_id` 与末事件的 `location_id` 比较，但文档没规定在用、遗失、报废等状态下位置该是什么，容易大量误报或漏报。 | 在规范里按状态定义位置口径，并做正负样例测试。 |
| B9 | v7 §2 | 每次请求都要查“会话族未撤销 + 用户状态 + 租户状态”，并且取消了 `auth_version`。 | 用一条联查，并明确缓存与失效策略。 |
| B10 | v7 §0.4 P2-5、README | 对账脚本空库返回 0 行不代表通过，README 已承认。但 v7 的 M4 门禁没要求“用代表性正负样例验证对账脚本本身能发现问题”。 | M3 门禁加：对账脚本的每一项都要有一个构造的错误样例并被抓到。 |
