# 报修CSV导入开发完成报告

日期：2026-11-01。依据：项目根《报修CSV导入指令包（给Codex）》；范围为离线收集表CSV导入命令。开发完成，待WorkBuddy独立验收；未提交或推送代码。

## 实现

新增 `django/apps/repair/management/commands/import_repairs.py` 及两级包初始化文件，新增 `django/tests/test_import_repairs.py`。支持全部指定CLI参数、中英文表头、UTF-8 BOM、分号/制表符与可选编码、对象编号/名称解析、历史状态与处理人校验、描述追加备注、确定性单号、重复跳过、dry-run与strict。

运行前执行require_runtime，拒绝DBA/迁移身份；按目标学校代码解析并锁定Tenant，复核停用/到期状态。所有目标、处理人、工单和身份查询带tenant；创建报修人直接调用ensure_lightweight_user，不自行创建User。工单与审计使用该轻量主体，不创建JWT或会话，不写照片、生成列或历史时间。

默认整批事务、每行保存点。校验、DB约束或审计失败仅回滚该行；其他行继续。仅本校工单号唯一冲突视作重复，其他IntegrityError不是重复。strict遇第一条行错误整批回滚；dry-run不写任何业务记录或审计，也不占用序列号。

## 对骨架的必要适配

1. 逐行异常在内层atomic退出后捕获，避免IntegrityError破坏外层事务后无法继续。
2. ensure_lightweight_user与core.audit实际签名兼容，已实测存在审计，无需“警告后继续保留未审计工单”的降级。审计失败按行错误回滚。
3. AssetCard没有active字段，改为校验关联Item的active；资产按asset_no精确查找。物品仍先code后name，场地按精确名称，歧义或外校记录拒绝。
4. 显式填写的非法target_id报错，不静默退回名称，防止填错编号仍导入另一对象。
5. strict按整批回滚解释，汇总真实成功数量为0，另列回滚/未处理数量。dry-run采用不写入的校验路径，防止“插入再回滚”仍消耗序列ID。
6. 整个文件先完成解码及CSV语法预检，再进入写事务；重复映射表头、缺必填表头、编码/文件错误返回2；行宽异常和业务字段错误返回1。
